# ST-26 需求倍率反馈 — 增量/减量调整

## === Layer 1: 架构约束 ===

### 工具权限
- 可调用: `aro__set_demand_uplift` / `aro__get_demand_uplifts` / `aro__query_stock` / `aro__query_orders` / `aro__query_order_items` / `aro__calc_replenishment`
- 禁止: 直接修改数据库

### 输出格式
返回 JSON:
```json
{
  "action": "set",
  "direction": "增量",
  "uplift_factor": 1.5,
  "change_pct": "增量50%",
  "effective_from": "2026-08-01",
  "effective_until": "2026-09-15",
  "reason": "开学季促销活动",
  "items": [{"bar_code": "6901234", "status": "created"}]
}
```

### 安全红线
- **必须收集明确的开始和结束时间**，禁止不设结束日期
- 时间窗口最长不超过 180 天
- uplift_factor 必须 > 0，不能为 0 或负数
- uplift_factor = 1.0 无意义，不写入
- 如果用户不给时间，必须主动追问

## === Layer 2: 业务逻辑 ===

### 增量需求契约
增量调整适用于建议量偏低且存在明确业务原因的场景：
- 促销活动: "开学季要搞活动"、"双11要多备"、"这个品要做促销"
- 季节性: "夏天到了冰品要多备"、"过年这个品卖得好"
- 经验判断: "这个品最近走量很快，建议量不够"

### 减量需求契约
减量调整适用于建议量偏高且存在明确业务原因的场景：
- 价格劣势: "这个品没价格优势不好出了"、"竞品降价了"
- 渠道变化: "这个门店不再卖这个品了"
- 库存积压: "这个品卖不动，库存太多了"
- 临期: "快过期了不想再进了"

### 倍率含义
| uplift_factor | 含义 | 示例 |
|---|---|---|
| 1.5 | 预测量×1.5, 增50% | 促销备货 |
| 2.0 | 预测量×2.0, 翻倍 | 大促 |
| 0.7 | 预测量×0.7, 减30% | 小幅减量 |
| 0.5 | 预测量×0.5, 减半 | 严重滞销 |
| 0.0001 | 几乎不补 | 停售过渡期(用极小值而非0) |

### 参数收集流程

#### 增量场景
1. 增量调整需要条码、倍率和有效期。
2. 系统识别: SKU=6901234, 方向=增量, 原因=开学季促销
3. **先查询当前建议量**，然后按默认+10%提议：
   - "当前该SKU建议量 80 CS。我先按增加10%（即88CS，倍率1.1）设置，您觉得合适吗？如果不够可以告诉我具体倍率或目标箱数。"
4. 明确倍率或目标约束：
   - "可以" / "行" → 直接用 1.1
   - "再多点" / "不够" → 再加10%变为 1.2，继续确认
   - "翻1.5倍" / "至少120箱" → 按用户明确值设置
5. **必须追问时间（如果没给）**: "活动从什么时候开始到什么时候结束？请提供具体日期，例如'8月1日到9月15日'"
6. 收集齐倍率 + 时间后调用 `aro__set_demand_uplift`
7. 展示结果并提醒: "已设置，该倍率将在 {effective_until} 后自动失效"

#### 减量场景
1. 减量调整需要条码、倍率和有效期。
2. 系统识别: SKU=xxx, 方向=减量
3. **先按默认-10%提议**：
   - "当前该SKU建议量 50 CS。我先按减少10%（即45CS，倍率0.9）设置，您觉得合适吗？"
4. 明确减量倍率或目标约束：
   - "可以" → 用 0.9
   - "再少点" → 再减10%变为 0.8，继续确认
   - "减半" / "砍到20箱" → 按用户明确值设置
5. **必须追问时间**: "减量从什么时候开始到什么时候？例如'从现在到月底'。如果不确定何时恢复，建议先设一个月，到时可以延长。"
6. 调用 `aro__set_demand_uplift`(uplift_factor=0.9, ...)`
5. 展示结果

#### 用户给绝对量而非倍率
1. 最低数量约束不等于需求倍率，必须使用对应的目标库存/订单约束能力。
2. 查询当前建议量 → 比如当前80CS
3. 计算倍率: 150/80 ≈ 1.88
4. 确认: "当前建议量80CS，设为1.9倍后约152CS，可以吗？"
5. 写操作已获得明确授权后设置

#### 查看当前生效的倍率
需求调整列表使用只读工具 `aro__get_demand_uplifts`。

#### 取消倍率
取消需求调整使用 `aro__set_demand_uplift`(action="remove")`。

### 生效机制
- 倍率写入 `demand_uplift` 表，`aro__calc_replenishment` 时自动对预测量乘以倍率
- 过了 `effective_until` 日期后自动失效，不需要用户手动取消
- 同一 SKU 可以有不同 ship-to 的不同倍率
- **设置/取消倍率后，必须自动调用 `aro__calc_replenishment`（不传 bar_code，全量重算）** 重新生成整张订单，并向用户展示受影响 SKU 的新建议量变化（旧→新）

### 关联 Skills
- 影响 **ST-03** 补货建议: 预测量 × uplift_factor → 改变建议量
- 与 **ST-22** ABC覆盖互补: ABC改分类方法，倍率改数量级
- 与 **ST-24** 异常过滤互补: 异常过滤清洗历史，倍率调整未来
- **ST-15** 决策解释可追溯倍率调整原因

## === Layer 3: 运营参数 ===

### 倍率限制
- 最大倍率: **5.0**（防止极端设置）
- 最小倍率: **0.01**（几乎为零但不完全停止）
- 时间窗口上限: **180 天**

### 默认行为
- 用户不给时间 → **必须追问，不允许默认**
- 相对开始日期按当天解析为 `effective_from`。
- 月末边界解析为当月最后一天 `effective_until`。
- 用户只说"一个月" → effective_from = 今天, effective_until = 今天+30天
